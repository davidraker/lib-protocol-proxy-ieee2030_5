# Source of the IEEE 2030.5 models

`sep.py` is generated by `regenerate.py` from the IEEE 2030.5 `sep.xsd` schema of the standard's supplemental material
(IEEE copyright; not in this repository). Obtain each edition from IEEE and point the `IEEE2030_5_SCHEMAS` environment
variable at a directory with one folder per edition named by year; the script takes the newest edition found, or the
`--schema` given. As of 2026-10-24 that is the 2023 edition (sha256 of the schema in the module's first line). It renders the schema with xsdata (`xsdata[cli]`, class and field names as in the
schema, one module) and folds three renderings that are not wire structure:

* the per-root-element anonymous extensions adding the `schemaVer` attribute (xsdata's `X_1` type plus `X(X_1)`
  element): the type keeps its name, its XML namespace and gains `schemaVer` as an optional attribute;
* simple-content types (`PerCent`, `PowerOfTenMultiplierType`, `TimeType`, `mRIDType`, the enumeration carriers, the
  2023 `*ControlType` setpoint wrappers): fields of those types take the value's scalar type, which is what the text
  content of the element is. The `disabled` attribute of the `*ControlType` wrappers is not represented; the lenient
  parser ignores it;
* xsdata's safe name `type_value` for the schema's `type` element goes back to `type`.

`from __future__ import annotations` is prepended because fields named like their type (`Notification.Resource`,
`DERControl.EventStatus`) would otherwise shadow the type when xsdata resolves annotations. The `*_r2_3` revision
markers (`xs:any` extension points added to every type in 2023) stay as optional fields; `convert.py` ignores them.

Before 2026-10-24 the module was the 2018 rendering from the GridAPPS-D `gridappsd-2030_5` distribution (0.0.2a37,
C. Allwardt, Battelle Memorial Institute; Apache-2.0 text shipped as `LICENSE` here). The 2023 rendering keeps every
2018 class and field (the editions are additive apart from the attribute above and `ServiceSupplierList`), so code
written against 2018 still works; `DERStatus.connectStatus` is now the real 2023 element and `convert.py` mirrors
its Connected bit to and from `genConnectStatus` for 2018 peers. `enums.py` and `constants.py` remain the 2018
transcriptions of the enumerations the schema documents in prose.

## Regenerating

```shell
pip install "xsdata[cli]"
python src/protocol_proxy/protocol/ieee2030_5/models/regenerate.py            # newest edition on the standards share
python src/protocol_proxy/protocol/ieee2030_5/models/regenerate.py --schema path/to/sep.xsd
```

Then run the tests; `convert.py`'s recognition of quantities, status structs and links is by field names, so a new
edition that reshapes those types shows up there first.
